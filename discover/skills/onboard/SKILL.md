name: onboard
description: Set up and install Intent-1 (formerly AI Autocomplete) in this project. Use when the user asks to onboard, add or install Intent-1 or AI Autocomplete.
allowed-tools: Read, Grep, Glob, LS
---

Onboard this project with Intent-1. Use the intent-1 MCP tools: call get_status first, then follow the guide it returns. If the server needs sign-in, start it yourself: call the server's authenticate tool. The link it returns carries a redirect_uri on a localhost port; that port closes when the sign-in finishes. Start one watcher with the shell tool, run in the background, that exits when the port closes: `bash -c 'for i in $(seq 300); do (exec 3<>/dev/tcp/127.0.0.1/PORT) 2>/dev/null || exit 0; sleep 2; done'` with PORT replaced. Try to open the link in the user's browser with a shell command (`open` on macOS, `xdg-open` on Linux, `start` on Windows; quote the link); skip this when the session runs on another machine, as over SSH. Then end your turn with the link written out in full and one line saying you will carry on by yourself once they approve, and that if the browser ends on a localhost page that does not load they should paste that page's full address here. Do not wait or poll in that turn. When the watcher exits, try get_status and carry on with onboarding without asking anything. If the user pastes a localhost address instead, finish the sign-in with the server's complete_authentication tool and carry on.

Some clients give you no authenticate tool, and the intent-1 tools are missing until the user has signed in. Start the sign-in with the client's own command then. In Codex, run `codex mcp login intent-1` with the shell tool in the background, read the link it prints, and end your turn with that link written out in full and one line saying that once they approve they should start a new session and run this command again: a session loads the server's tools only when it starts. In a client that gives you no way to start the sign-in, tell the user how to sign in with that client and stop.

The user may write instructions with the command: what the box should offer first, what it must never suggest, how suggestions should be written, or which parts of the app to cover. Put every such instruction, in the user's own words, in your first message to the onboarding agent, after what you read from the code. They are the user's decisions: never drop or reword one.

This copy of the skill does not approve tools ahead of time. Before your first tool call, tell the user in one line that Claude will ask them to approve the intent-1 tools, file edits and shell commands, and that choosing the option that stops asking for the session keeps the setup moving.
